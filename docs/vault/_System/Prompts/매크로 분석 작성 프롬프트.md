# 매크로 분석 작성 프롬프트

**용도:** 모아둔 골격을 실제 분석 산출물로 바꾸는 절차. 이게 없으면 `02_Reports/`는
그냥 요약 저장소로 끝난다.

**핵심 전제:** 모델 가중치는 안 바뀐다. "분석 스타일 학습"은 **매 세션 골격을 명시적으로
읽어 few-shot으로 쓰는 것**이다. 그래서 아래 1단계를 건너뛰면 이 시스템은 작동하지 않는다.

---

## 0. 시작 전 확인

세션 시작 훅이 알려주는 두 숫자를 본다.

```
MacroVault: 큐 미처리 N건, 사후채점 대기 M건
```

- **사후채점 대기가 있으면 채점을 먼저 한다.** 새 분석보다 우선이다 — 검증되지 않은
  판단이 쌓이는 것이 이 시스템의 가장 큰 실패 모드다.
- 큐 미처리는 분석 후에 처리해도 된다.

## 1. 골격 소환 (필수 — 건너뛰지 말 것)

`03_MOC/리포트 골격 MOC.md`를 열고 **3~5개**를 고른다. 고르는 기준:

| 쓰려는 글 | 소환할 class |
|---|---|
| 레짐 판단 / 전망 | `forecast` 2 + `diagnostic` 2 |
| 제도·구조 설명 | `structural` 2 + `diagnostic` 1 |
| 현장·단기 코멘터리 | `diagnostic` 2 + `commentary` 1 |

고른 노트의 **1~5번 절(출발 질문 · 지표 연결 · 인과 사슬 · 반대 시나리오 · 트레이드오프)만**
읽는다. Red Team과 Comment는 내 작업이지 스타일 예시가 아니다.

읽고 나서 **무엇을 모방할지 한 줄로 적고 시작한다.** 예:
> "BIS식 — 배경은 20년 시계열, 증거는 3년으로 좁힌다. 주장을 사용량으로 닫는다."

## 2. 작성 규칙 (골격에서 추출된 것)

1. **H1은 제목이 아니라 결론 한 줄.**
2. **지표는 순서가 있다.** 무작정 나열하지 말고 "무엇을 보이려고 이 지표를 여기 놓았는가"가
   각 지표마다 있어야 한다. 없으면 그 지표는 뺀다.
3. **인과는 화살표로 방향을 명시한다.** "관련이 있다"는 인과가 아니다.
4. **저자의 주장과 내 추론을 절로 분리한다.** 섞이면 노트 전체의 신뢰도가 무너진다.
5. **트레이드오프를 쓴다.** "얻는 것 / 잃는 것 / 실제 선택" 3열. 정책 문서에서 가장
   재사용도가 높은 형식이며, 시장 해석에 그대로 전용된다.
6. **무효화 조건은 숫자로.** "상황이 나빠지면"은 조건이 아니다.
7. **Red Team 필수.** 기관 문서라고 통과시키지 않는다. 번호를 매긴다.
8. **모르는 것은 "원문에 없음"이라고 쓴다.** 지어내지 않는다.
9. **역사 유비를 쓸 때는 조건으로 분해한다.** "지금은 1940년대와 비슷하다/다르다"는 정보가 없다.
   **성공을 만든 조건을 낱낱이 나열하고 조건별로 현재 성립 여부를 채점한다.**
   → `_System/docs/ARGUMENT_METHOD.md` §3
10. **통제 가능한 변수와 불가능한 변수를 가른다.** 정책 논쟁의 대부분은 통제 가능한 것만 세다가 틀린다.
   취약점은 통제 불가능한 쪽에 있다. → 같은 문서 §4
11. **비율 지표를 쓰면 수준 지표를 같이 본다.** "점유율이 떨어졌다"와 "생산량이 줄었다"는 다른 말이다.
   → 같은 문서 §7
12. **내 논지가 틀렸다고 인정할 조건을 쓴다.** 상대에게 씌운 체크리스트는 **내 논지에도 씌운다.**
   이걸 빠뜨리는 것이 유료 리서치에서 가장 흔한 결함이다. → 같은 문서 §12·체크리스트 13
13. **내 결론이 내 포지션과 일치하면 가중치를 낮춘다.** 남의 글을 읽을 때도 같은 잣대를 적용한다.
14. **남의 노트에서 수치를 가져올 때 노트 등급이 아니라 그 수치의 `cited_data` 등급을 본다.**
   전사본이 `verification: n-a`인 것은 **"화자가 그렇게 말했다"에 대한 등급**이지
   그 안에 재인용된 3자 데이터의 등급이 아니다. → `_System/docs/FRONTMATTER_VOCAB.md` 「cited_data」
15. **반증 조건과 트리거 임계값에는 D2(재현 완료)만 쓴다.** 재현 못 하는 숫자로는 채점이 안 된다.

## 3. 산출물 배치

| 쓰려는 글 | 위치 | 템플릿 |
|---|---|---|
| 개별 리포트 골격 | `02_Reports/` | `T_ReportSkeleton.md` |
| 레짐 판단 | `05_Regime/` | `T_RegimeView.md` |
| 데이터 해석 | 해당 주차 | `T_Interpretation.md` |
| 단발 주장 | `04_Zettel/` | `T_Zettel.md` |

작성 후 **반드시** 해당 MOC에 배치 등록하고, 교차 논점을 **이어서 번호 매긴다**
(기존 번호는 건드리지 않는다).

## 4. 채점 루프 (이 시스템의 최종 산출물)

`scored: 미채점`인 노트를 훑어 `next_check`가 도래한 것을 채점한다.

- **검증 가능한 명제만 채점한다.** "성장세 둔화"는 참·거짓 판정이 불가능하다 → 애초에
  채점표에 올리지 않는다.
- **절대 오차와 방향을 나눠서 본다.** 방향이 맞고 크기만 틀린 것과, 방향 자체가 틀린 것은
  신뢰도 함의가 완전히 다르다.
- **정책 방향 명제는 물가 명제보다 훨씬 빨리 채점된다.** 회의는 6~8주마다 열린다.
  실제 사례: 2026-06 FOMC 의사록의 "매파 전환" 판단이 **7-29 성명서 9–3 반대표**로
  6주 만에 확인됐다. → **투표 분포는 정책금리보다 먼저 움직인다.**
- 채점 결과는 `02_Reports/`의 해당 노트 안에 **누적**한다. 별도 노트로 빼지 않는다.

채점이 쌓이면 기관별 신뢰도가 감이 아니라 **기록**이 된다. 그게 최종 목적지다.

## 소환 예시 (실제로 작동한 조합)

**"지금 레짐이 뭔가"를 쓸 때 (2026-08 기준):**

- [[2026-06 ECB Economic Bulletin — 전쟁 인플레이션에 대한 선제 인상]] (`forecast`) — 시나리오 강건성 논법
- [[2026-06 FOMC Minutes — 완화 편향 문구 삭제와 금리 동결]] (`diagnostic`) — 투표 분포 읽기
- [[2026-07 Fed Beige Book — 연료비가 갉아먹는 소비]] (`diagnostic`) — 현장 질감
- [[2026-06 BIS Quarterly Review — 중앙은행 대출오퍼레이션의 진화 (Kijima·McGuire·Rime)]] (`structural`) — 트레이드오프 표

이 조합으로 [[RegimeView_2026-08]]을 썼다. 4건을 나란히 놓았을 때만 보이는 것이
있었다 — **성장이 약한 쪽이 먼저 올렸다**는 역전은 한 건씩 읽으면 안 보인다.
