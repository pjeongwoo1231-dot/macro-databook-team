# 시황을 HTML로 만들 때 주는 요청서

> **쓰는 법.** E-1로 뽑은 분석 본문을 아래 요청서 **맨 아래에 붙여서** 통째로 준다.
> 분석을 다시 쓰게 하지 않는다 — **디자인만** 맡긴다.

> ⚠ **이 요청서가 막는 두 가지 사고**
> ① 디자인하다 **숫자가 바뀐다** (반올림·표 축약·항목 병합) → §0이 막는다.
> ② **준비 과정이 발표자료에 실린다** (as-of 설명·방법론·자기검사) → §1이 막는다.
> ②는 [[좋은 시황의 규칙]] §0이 이미 금지한 것이다 —
> *"볼트 노트를 예쁘게 만들어 보고서라고 내지 않는다."*

---

## 붙여넣는 요청서

```text
아래 매크로 주간분석을 학회 발표용 단일 HTML 페이지로 만들어줘.

【0. 숫자와 문장은 건드리지 마】
- 숫자·기준일·부호를 하나도 바꾸지 마. 반올림·단위환산·표 축약 전부 금지.
- 문장을 다시 쓰지 마. 표현이 어색해도 그대로 둔다.
- 항목을 합치거나 빼지 마. 표가 길면 스크롤로 해결한다.
- 원문에 없는 수치를 만들지 마. 차트도 표에 있는 값으로만 그린다.

【1. 본문에 넣지 말 것 — 이게 제일 중요하다】
이건 **발표자료**지 작업일지가 아니다. 아래는 본문에서 빼고,
꼭 남겨야 하는 것만 맨 끝 <details> 부록으로 접는다.

  ✗ "무엇을 근거로 썼나" 같은 방법론 서두
  ✗ as-of·--asof·창 경고 등 도구 사용 설명
  ✗ 자기검사 체크리스트, 금지문장 대조표
  ✗ 데이터 신선도표
  ✗ "미수집"·"계열 없음" 같은 수집 상태 보고

  → 이런 건 읽는 사람에게 아무 정보가 아니다. **결론과 근거만 남긴다.**

단, **숫자의 신뢰도에 직접 걸리는 한계**는 부록에 남긴다:
표본이 짧은 백분위, 미검증 주장, 확정 전 수치. 본문에서는 각주 한 줄로 처리한다.

【2. 페이지 구조】
경제학회 12명이 화요일 세션에서 함께 읽는다. 읽는 사람은 거시 초보 2학년이다.

  H1        결론 한 줄. 제일 크게. 부제는 날짜만.
  요약       핵심 3~4개를 카드로. 숫자 하나 + 한 줄 해석.
  본문       축별로. 각 축은 [차트 또는 표] + [그래서 무엇인가] 두 덩어리.
  판정       레짐 유지/변경 · 트리거 상태
  전망       무효화 조건(숫자) · 다음 주에 볼 것
  부록       <details>로 접는다

처음 나오는 용어는 그 자리에서 한 줄로 푼다(예: "BEI = 명목금리 − 물가연동채 금리,
시장이 매긴 기대인플레이션"). 각주가 아니라 본문 안에서.

【3. 그래프 — 필수다. 표만 있으면 실패다】
숫자 표를 그대로 옮기지 마라. **표에 있는 값으로 반드시 그림을 만든다.**

  · 시계열이 있으면 선 그래프. 축 라벨과 최근값 주석을 붙인다.
  · 기간별 변화(1주/1개월/3개월)는 0을 기준으로 좌우로 뻗는 막대.
    부호가 갈리는 것이 한눈에 보여야 한다.
  · 백분위는 0~100 띠 위에 현재 위치를 점으로. 극단값이 극단으로 보이게.
  · 분포·기저율은 히스토그램 또는 점 분포 + 중앙값 선.
  · 자금 흐름처럼 방향이 반대인 두 계열은 위아래 대칭 막대.

전부 인라인 SVG로 그린다. 외부 라이브러리·이미지·CDN 금지.
데이터가 부족해 못 그리는 것은 그리지 말고 표로 둔다 — 지어내지 마라.

【4. 형식】
- 단일 HTML 파일, 완전 자립. CSS·JS 전부 인라인. 외부 요청 0건.
- 한글 본문: -apple-system, "Segoe UI", "Malgun Gothic", sans-serif
- 라이트/다크 둘 다. 색은 CSS 변수 + prefers-color-scheme.
- 폭 375px에서 가로 스크롤 없음. 넓은 표는 표만 가로 스크롤.
- 인쇄 시 표가 페이지 중간에서 잘리지 않게.
- 위키링크 [[...]]는 대괄호를 지우고 강조로 바꾼다.

【5. 톤】
중앙은행 리뷰(BIS·ECB) 지면을 참고한다. 여백이 넓고, 그림과 표가 주인공이고,
강조는 굵기와 여백으로만 한다. 장식·이모지·형광색 금지.
숫자는 tabular-nums. 음수는 색이 아니라 부호로 구분한다.

【6. 다 만든 뒤 검사】
- [ ] 원문의 모든 숫자가 그대로인가
- [ ] 방법론·자기검사·신선도표가 본문에서 빠졌는가
- [ ] 축마다 그림이 하나 이상 있는가
- [ ] 다크모드에서 그림의 축·라벨이 읽히는가
- [ ] 375px에서 가로 스크롤이 없는가
- [ ] 외부 요청이 0건인가

--- 아래가 페이지로 만들 분석 본문이다 ---

(여기에 E-1 결과물을 붙여넣는다)
```

## 왜 §1이 §0보다 중요한가

[[좋은 시황의 규칙]] §0의 표가 이미 답을 갖고 있다:

| | 볼트 노트 | 보고서 |
|---|---|---|
| 목적 | 기록·감사 | **판단 전달** |
| 독자 | 미래의 나 | **사람** |
| 신선도표 · 규칙 대조 · 자기검사 | **필수** | **금지** |

**두 산출물의 독자가 다르다.** as-of가 언제인지, 어떤 규칙을 대조했는지는
**미래의 내가 감사할 때** 필요한 것이지 발표를 듣는 사람에게는 소음이다.

그 규칙이 만들어진 계기도 같은 실수였다 — *"2026-08-25 초안이 그 실수였고,
절반이 '내가 어떻게 일했는가'였다."* 디자인 단계에서 이게 다시 살아나면
같은 실패를 반복한다.
