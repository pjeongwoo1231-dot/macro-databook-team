# 팀원이 붙여넣는 프롬프트

> **이 노트가 왜 따로 있나.** 볼트에는 이미 규칙이 다 있다 —
> [[좋은 시황의 규칙]](보고서를 어떻게 쓰나) · [[시황 분석 진입점]](무엇을 읽나) ·
> [[제텔 소환 인덱스]](무엇이 금지돼 있나). **문제는 AI가 그걸 스스로 열지 않는다는 것이다.**
> 그냥 "시황 써줘"라고 하면 일반 지식으로 그럴듯한 글을 쓰고, 볼트가 반박해 둔 문장을
> 그대로 쓴다. 이 프롬프트는 **읽는 순서를 강제하는 장치**다. 새 규칙이 아니다.

> ⚠ **실제로 겪은 실패다.** 절차만 따르고 제텔을 안 본 세션이 잘못된 결론을 냈다.
> 그래서 §1(금지·제한 규칙)을 **분석 전에** 읽게 만든다.

---

## A. 일간 시황 — 이걸 그대로 복사해 붙여넣는다

```text
MacroVault에서 오늘 시황을 써줘.

【반드시 이 순서로 먼저 읽을 것 — 건너뛰면 결론이 틀린다】
1. 03_MOC/좋은 시황의 규칙.md
2. 03_MOC/시황 분석 진입점.md — §1 판정 규칙 표 전체 + §2 금지 문장
3. 03_MOC/제텔 소환 인덱스.md — §1 금지·제한 규칙
4. 05_Regime/ 의 최신 RegimeView — 현재 유효 상태와 트리거 상태
5. 04_DataBook/ 의 최신 DataBook_YYYY-MM-DD.md — 오늘 값
6. 04_DataBook/_News/ 의 최신 NewsDigest — 어제 대비 새로 뜬 것만

읽은 뒤, 본문을 쓰기 전에 「무엇을 근거로 쓰겠다」를 3줄로 먼저 말해.

【네 축을 따로 판정한다. 서로 어긋나면 억지로 합치지 말고 어긋난 채로 보고해】
- 거시   : 성장 · 물가 · 정책금리
- 유동성 : 순유동성 · HY OAS · NFCI
- 수급   : 외국인/기관 순매수 · 신용융자 · 대차 (01_Indicators의 수급 패널 노트)
- 가격   : 지수 · 환율 · 금리 · 원자재의 당일 반응

【주장을 쓰는 규칙】
- 주장 하나에 근거는 「추세 · 사례 · 이론」 중 최소 둘. 셋 다 없으면
  주장으로 올리지 말고 "관측"이라고 적어.
- "X라서 Y가 된다"를 쓰기 전에 과거 같은 배열의 기저율을 먼저 세라.
  못 셌으면 "기저율 미측정"이라고 본문에 명시해.
- 인과는 화살표로 쓰고 노드를 소환해: [[A]] ↑ → [[B]] ↑.
  "관련이 있다"는 인과가 아니다.
- 모든 수치에 기준일을 병기해. DataBook에 STALE 표시가 있으면 그 사실을 본문에 적어.
- 계수·표를 인용하려면 출처 노트의 frontmatter가 verification: full 이어야 한다.
  partial이면 서술만 인용하고, 없으면 "원문 미대조"를 병기해.
- 각 해석에 확신도(상/중/하)를 붙여.
- 모르는 것은 "관측 없음"이라고 써. 지어내지 마.

【마지막에 반드시】
- Red Team : 내 결론을 죽이는 반대 논리 2개, 번호를 매겨서
- 무효화 조건 : 숫자로. "상황이 나빠지면"은 조건이 아니다
- 자기검사 : 시황 분석 진입점 §2 금지 문장을 하나씩 대조한 결과

【형식】
보고서로 써. 데이터 신선도표·규칙 대조·자기검사는 본문에 섞지 말고 맨 끝에 따로 붙여.
결론은 H1 한 줄로 먼저. 근거는 셋까지.
해석은 네가 완결해서 내놔 — 내가 채울 빈칸이나 과제를 남기지 마.
```

## B. 이해 안 되는 곳을 되묻는다 (과외 모드)

시황을 받은 뒤 막히는 지점마다 쓴다. **모르는 걸 넘어가지 않는 게 이 시스템의 핵심이다.**

```text
방금 시황의 "○○○" 부분이 이해가 안 돼.
왜 그렇게 되는지 비유를 들어 단계별로 설명해줘.
내가 그 개념을 모른다고 가정하고 처음부터. 결론만 다시 말하지 말고 과정을 보여줘.
```

## C. 저장하고 나중에 채점받게 만든다

**이걸 안 하면 분석이 검증되지 않고 흩어진다.** 이 시스템의 최종 산출물은 채점 기록이다.

```text
이 시황을 05_Regime/시황 YYYY-MM-DD — <결론 한 줄>.md 로 저장해줘.
프론트매터는 볼트 표준(_System/docs/FRONTMATTER_VOCAB.md)을 따르고,
예측을 적었으면 [[기관 예측 신뢰도 스코어카드]] §5에 사전 등록하고 next_check를 잡아줘.
```

## E. 세션 준비 — 발표 담당자용 ★

> **학회 리듬.** 세션은 **매주 화요일**, 다음 세션 준비는 **수·목부터** 시작한다.
>
> **기준 시점(as-of)을 직전 세션일로 고정한다.** 준비를 수요일에 하든 일요일에 하든
> 같은 자료가 나온다 — 시점이 움직이면 수요일에 쓴 문장이 월요일에 틀린 문장이 되고
> 글을 다시 써야 한다. 열두 명이 같은 자료를 본다는 보장도 없어진다.
>
> ⚠ **as-of 고정은 "일주일치만 본다"는 뜻이 아니다.**
> 거시분석의 재료는 **그 시점까지의 전체 상태와 장기 시계열**이다.
> 지표마다 2000년부터의 이력이 있고(계열 177개), [[좋은 시황의 규칙]]이 요구하는
> **「추세」와 「사례(기저율)」는 일주일치로는 아예 낼 수 없다.**
> 변경분 목록은 **어디를 새로 볼지 고르는 길잡이**일 뿐 재료가 아니다.
>
> `weekly`가 세 층을 함께 준다:
>
> | 층 | 무엇 | 쓰임 |
> |---|---|---|
> | **§1 전체 상태** | `DataBook_<as-of>.md` — 지표 328개 | **본 재료.** 여기서 시작한다 |
> | §2 변경분 | 지난 한 주에 바뀐 것 | 어디를 새로 확인할지 |
> | **§3 장기 시계열** | `output/history/` CSV 177개, 2000년~ | **추세·기저율.** 근거 3축이 여기 걸려 있다 |
>
> **대가와 처리법.** 발표일엔 as-of가 일주일 뒤처진다. `weekly`가 끝에
> **「as-of 이후 N건 변경」** 을 찍어준다. 발표 당일 아침에 그것만
> **한 절로 맨 앞에 덧붙인다. 본문은 고치지 않는다.**

### E-1. **이것만 붙여넣는다** (터미널 명령도 AI가 알아서 돌린다)

```text
MacroVault로 이번 주 통합분석을 써줘.

【0단계 — 자료부터 직접 뽑을 것】
먼저 터미널에서 이걸 실행하고 출력을 근거로 써:

    cd ~/macro-databook-team     # 부트스트랩이 여기에 설치한다
    python -m databook weekly

  폴더가 없으면: git clone https://github.com/pjeongwoo1231-dot/macro-databook-team ~/macro-databook-team
  (팀장 PC는 예전 경로에 있다: ~/OneDrive/ドキュメント/databook-autopilot/deploy_macro-databook)

이 명령 하나가 ① 수집 상태 ② 기준 시점의 전체 상태(본 재료) ③ 지난 한 주 변경분
④ 장기 시계열 위치 ⑤ 새 기사 ⑥ 손댈 자리를 다 뱉는다. 날짜는 자동 계산된다.
출력 맨 위의 **기준 시점(as-of)을 보고서 첫 줄에 그대로 적어.**
[창 경고]가 있으면 그것도 적어 — 그날 수집이 없어 다른 날로 대체됐다는 뜻이다.
맨 아래 [창 이후]는 **본문에 넣지 마.** 발표 당일에 따로 덧붙일 몫이다.

**§2(변경분)만 보고 쓰지 마.** 그건 어디를 볼지 고르는 목록이다.
주장을 세울 땐 §1의 DataBook에서 그 지표의 현재 상태와 note를 읽고,
**추세와 기저율은 §3의 장기 CSV를 직접 세서** 낸다.
「지난주 대비 +0.3」 같은 문장만 늘어놓으면 그건 거시분석이 아니라 변경 로그다.

【1단계 — 볼트 규칙을 읽을 것. 순서 고정】
1. 03_MOC/좋은 시황의 규칙.md
2. 03_MOC/시황 분석 진입점.md — §1 판정 규칙 표 전체 + §2 금지 문장
3. 03_MOC/제텔 소환 인덱스.md — §1 금지·제한 규칙
4. 05_Regime/ 최신 RegimeView — 현재 유효 상태 + 트리거 전체 상태
5. 05_Regime/ 지난주 노트 — 채점 대상

읽고 나서 본문 전에 「무엇을 근거로 쓰겠다」를 3줄로 먼저 말해.

【2단계 — 주간이라서 달라지는 것】
- 하루 등락이 아니라 **일주일간의 방향**. 중간에 뒤집혔으면 그 사실 자체를 써.
- **트리거 전수 점검** — 각 트리거가 발동/근접/무관 중 무엇인지 표로.
  근접이면 남은 거리를 숫자로.
- **레짐 갱신 판정** — 바꿀 근거가 없으면 "레짐 유지"라고 명시해.
  매주 새 서사를 만들지 마.
- **지난주 판단 채점** — 맞았나 틀렸나, 방향과 크기를 나눠서.

【3단계 — 주장 규칙】
- 근거는 「추세·사례·이론」 중 최소 둘. 셋 다 없으면 "관측"으로 강등.
- 기저율을 먼저 세고, 못 셌으면 "기저율 미측정" 명시.
- 인과는 화살표 + 노드 소환: [[A]] ↑ → [[B]] ↑. "관련이 있다"는 인과가 아니다.
- 모든 수치에 기준일 병기. STALE이면 본문에 밝힐 것.
- 계수 인용은 verification: full 만. partial은 서술만. 없으면 "원문 미대조".
- 확신도(상/중/하)를 붙이고, 모르면 "관측 없음".

【4단계 — 네 축을 따로 판정. 어긋나면 어긋난 채로 보고】
거시(성장·물가·정책금리) / 유동성·신용 / 수급 / 가격

【마지막】
- Red Team 2개(번호) · 무효화 조건(숫자) · §2 금지문장 대조 결과
- **다음 주에 볼 것 3개** — 무엇이 어떻게 나오면 판단이 바뀌는지 숫자로

【형식 — 남이 공부할 자료다】
결론 H1 한 줄 먼저. 근거는 축당 셋까지.
초보자가 읽는다는 전제로, 처음 나오는 개념은 그 자리에서 한 줄로 풀어 써.
빈칸·과제를 남기지 마. 자기검사·신선도표는 본문에 섞지 말고 맨 끝에 따로.
```

> **`python -m databook weekly` 가 하는 일** — 예전엔 담당자가 `diff --since <날짜>` ·
> `news --new` · `todo` 를 따로 치고 직전 세션일을 손으로 셌다. 매주 틀릴 여지만 있었다.
> 이제 한 줄이다. 기준 시점(as-of)은 **직전 화요일**로 고정된다 — 세션 당일에 돌려도
> 7일 전을 잡는다(오늘과 오늘을 비교하지 않는다). 발표까지 D-day도 함께 찍는다.

### E-1-a. 발표 자료로 쓸 때만 덧붙인다 (선택)

```text
위에 더해서 두 가지만 더 해줘.
1. 03_MOC/리포트 골격 MOC.md 에서 골격을 3~5개 소환하고, 무엇을 모방할지 한 줄로 밝히고 시작해.
2. 04_Zettel/ 에서 이번 판정에 걸리는 제텔을 실제로 열어 인용해.
   제목만 나열하지 말고, 그 제텔이 이번 결론을 지지하는지 반박하는지 밝혀.
```

> ⚠ **수집은 매일 18:30에 자동으로 돈다**(작업 스케줄러 `macro-databook-daily`).
> 분석은 주 1회여도 수집은 매일이어야 한다 — `sectors`·`lending`·토스 1분봉은
> **그날 상태만 주고 소급이 안 된다.** 안 돌린 날은 영영 빈칸이다.

### E-1-b. 준비 기간에 뭘 하나

창이 고정이라 **자료를 다시 뽑을 필요가 없다.** 남는 건 글 쓰는 일이다.

| 시점 | 할 일 |
|---|---|
| **수·목** | `weekly` 한 번. 지난 세션 채점 + 트리거 점검 + 본문 초안 |
| | **§3 장기 CSV로 기저율을 잰다** — 이게 준비 시간의 대부분을 차지한다 |
| **금·월** | 본문 마무리. **자료는 그대로다** — 다시 안 뽑아도 된다 |
| **화 아침** | `python -m databook diff --since <직전 세션일>` 한 번.<br>「세션 이후 변화」 한 절만 맨 앞에 붙인다. **본문은 손대지 않는다** |

발표 당일에 붙이는 절은 이 정도면 된다:

```text
직전 세션(<날짜>) 이후 새로 들어온 것만 정리해줘.
python -m databook diff --since <날짜> 를 돌려서, 이번 발표의 결론을
**뒤집을 만한 것이 있는지**만 판정해. 없으면 "없음"이라고 한 줄로 써.
```

### E-2. 끝나면

```text
이 통합분석을 05_Regime/주간 YYYY-MM-DD — <결론 한 줄>.md 로 저장하고,
검증 가능한 명제는 [[기관 예측 신뢰도 스코어카드]] §5에 사전 등록하면서
next_check를 다음 주 화요일로 잡아줘.
```

공유는 볼트에 저장하는 것으로 끝난다 — **Sync로 전원에게 자동 전파된다.**
따로 파일을 보내지 않는다.

## 자주 나오는 문제

| 증상 | 원인 | 대응 |
|---|---|---|
| 볼트가 반박해 둔 문장이 그대로 나옴 | §1·§2를 안 읽음 | "시황 분석 진입점 §2를 하나씩 대조해줘"를 다시 요구 |
